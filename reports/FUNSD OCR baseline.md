# FUNSD OCR baseline

## Result

The current `fastdocparse` image-only PDF path was run against all 50 documents
in FUNSD's official test split, using the repository's positioned RapidOCR
backend. The dataset was downloaded from the official FUNSD site; its archive
SHA-256 matched the checksum published by docTR (`c31735649e4f441bcbb4fd0f379574f7520b42286e80b01d80b445649d54761f`).

| Metric | Result |
| --- | ---: |
| Ground-truth approximate lines | 1,355 |
| OCR predicted lines | 1,518 |
| Line precision / recall / F1 at IoU ≥ 0.50 | 0.790 / 0.885 / 0.835 |
| Line precision / recall / F1 at IoU ≥ 0.75 | 0.682 / 0.764 / 0.721 |
| CER on spatially matched lines (IoU ≥ 0.50) | 0.302 |
| Macro per-document F1 at IoU ≥ 0.50 | 0.833 |
| Macro per-document CER | 0.293 |

The complete per-document results and metric definitions are in
[`funsd-ocr-baseline.json`](funsd-ocr-baseline.json). The reproducible runner is
[`benchmarks/funsd/benchmark_ocr.py`](../benchmarks/funsd/benchmark_ocr.py).

## Interpretation and limitations

This is an initial **OCR and line-localization** baseline, not a benchmark of
layout-region or table reconstruction. FUNSD annotates scanned form words,
entities, and key-value links; it does not provide the general page-region
taxonomy or item-table grids needed to score those two tasks. Ground-truth lines
here are generated by clustering annotated word boxes with a documented vertical
overlap rule. They are approximate reference lines, not official line-level
annotations. Text CER is computed only for spatially matched lines; unmatched
reference text is counted as deletion and unmatched OCR text as insertion.

The result shows a useful baseline with high line recall but appreciable OCR
errors and less precise localization at the stricter IoU threshold. It also shows
why table/layout quality should not be inferred from OCR metrics: recovering the
right words is not the same as putting them into the right page regions or cells.

## Next benchmark slices

1. Add CORD/SROIE to check receipt-specific OCR and grouping using their word
   boxes, line/group metadata, or OCR transcriptions where available. Review each
   dataset version and license before adding it.
2. Add cTDaR for table-region detection and table recognition on modern and
   historical images. Keep detection and structure scores separate.
3. Use FUNSD/FUNSD+ to benchmark form entities and key/value relations only once
   a comparable predicted entity/relation representation exists.
4. Evaluate DocLayNet for generic region classification, but report its scan and
   business-document domain limitations; it is not a substitute for scanned
   invoice/receipt evaluation.
5. Only after these baseline measurements should an optional layout/table model
   be integrated or trained. Preserve the existing native-PDF path and compare
   model additions against these fixed datasets and splits.
